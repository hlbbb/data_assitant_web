## 7.1 CASE WHEN：如果…就…否则…

一句话：CASE WHEN 就是 SQL 里的 if-else，让你在查询时做条件判断。

**生活比喻**：

你在超市收银台，系统要判断：
- 会员 → 打8折
- 非会员 → 原价

这就是 CASE WHEN 干的事。

### 简单 CASE（等值匹配）

```sql
-- 简单CASE：拿一个值去匹配
SELECT
    order_status,
    CASE order_status
        WHEN 'paid' THEN '已支付'
        WHEN 'shipped' THEN '已发货'
        WHEN 'completed' THEN '已完成'
        WHEN 'cancelled' THEN '已取消'
        ELSE '未知状态'
    END AS status_cn
FROM orders;
```

### 搜索 CASE（条件判断）

```sql
-- 搜索CASE：自己写条件表达式
SELECT
    product_name,
    price,
    CASE
        WHEN price >= 500 THEN '高端'
        WHEN price >= 200 THEN '中端'
        WHEN price >= 50 THEN '入门'
        ELSE '廉价'
    END AS price_level
FROM products;
```

**好的写法 vs 不好的写法**：

```sql
-- 不好：多层嵌套 IF（MySQL特有，可读性差）
SELECT
    IF(price >= 500, '高端',
       IF(price >= 200, '中端',
          IF(price >= 50, '入门', '廉价')
       )
    ) AS price_level
FROM products;

-- 好：CASE WHEN，清晰直观
SELECT
    CASE
        WHEN price >= 500 THEN '高端'
        WHEN price >= 200 THEN '中端'
        WHEN price >= 50 THEN '入门'
        ELSE '廉价'
    END AS price_level
FROM products;
```

### 案例1（基础）：订单金额分级

```sql

    order_id,
    total_amount,
    CASE
        WHEN total_amount >= 1000 THEN '大单'
        WHEN total_amount >= 500 THEN '中单'
        WHEN total_amount >= 100 THEN '小单'
        ELSE '微小单'

    CASE
        WHEN total_amount >= 1000 THEN total_amount * 0.95  -- 大单95折

FROM orders
```

### 案例2（进阶）：CASE WHEN + 聚合，实现分组统计

```sql
-- 统计每个价格区间的商品数量
SELECT
    CASE
        WHEN price >= 500 THEN '500元以上'
        WHEN price >= 200 THEN '200-500元'
        WHEN price >= 50 THEN '50-200元'
        ELSE '50元以下'
    END AS price_range,
    COUNT(*) AS product_count,
    ROUND(AVG(price), 2) AS avg_price
FROM products
GROUP BY
    CASE
        WHEN price >= 500 THEN '500元以上'
        WHEN price >= 200 THEN '200-500元'
        WHEN price >= 50 THEN '50-200元'
        ELSE '50元以下'
    END
ORDER BY avg_price DESC;
```

**运行结果：**

```text
+-------------+---------------+-----------+
| price_range | product_count | avg_price |
+-------------+---------------+-----------+
| 500元以上   |             6 |   2749.00 |
| 200-500元   |             5 |    335.00 |
| 50-200元    |            15 |    117.00 |
| 50元以下    |             4 |     44.00 |
+-------------+---------------+-----------+
```

**教学点 #1**：CASE WHEN 两种形式——简单CASE做等值匹配，搜索CASE做条件判断。分析场景90%用搜索CASE。

**教学点 #2**：CASE WHEN 可以和 GROUP BY 搭配，把条件分类作为分组依据。

**教学点 #3**：CASE WHEN + 聚合函数，是实现行转列的核心技巧，下一节就用到。

## 7.2 日期函数大全

一句话：日期函数让你从时间维度切数据，这是分析的基本功。

**生活比喻**：

日期函数就像日历上的各种标记——今天是几号？这周第几天？两个日子隔了多久？这些函数帮你回答这些问题。

### 核心日期函数一览

```sql
-- 获取当前日期和时间
SELECT NOW();           -- 2026-05-12 14:30:00
SELECT CURDATE();       -- 2026-05-12
SELECT CURTIME();       -- 14:30:00

-- 提取年月日
SELECT YEAR('2026-05-12');    -- 2026
SELECT MONTH('2026-05-12');   -- 5
SELECT DAY('2026-05-12');     -- 12
SELECT QUARTER('2026-05-12'); -- 2（第二季度）
SELECT DAYOFWEEK('2026-05-12'); -- 2（周一，MySQL中1=周日）
SELECT DAYNAME('2026-05-12');  -- Monday

-- 日期格式化
SELECT DATE_FORMAT('2026-05-12', '%Y年%m月%d日'); -- 2026年05月12日
SELECT DATE_FORMAT('2026-05-12', '%Y-%m');        -- 2026-05

-- 日期运算
SELECT DATEDIFF('2026-05-12', '2026-01-01');  -- 131（相差天数）
SELECT DATE_ADD('2026-05-12', INTERVAL 7 DAY);    -- 2026-05-19
SELECT DATE_ADD('2026-05-12', INTERVAL 1 MONTH);  -- 2026-06-12
SELECT DATE_SUB('2026-05-12', INTERVAL 30 DAY);   -- 2026-04-12

-- 日期截断（取月初、年初）
SELECT DATE_FORMAT(NOW(), '%Y-%m-01');  -- 当月第一天
SELECT DATE_SUB(DATE_FORMAT(NOW(), '%Y-%m-01'), INTERVAL 1 MONTH); -- 上月第一天
```

### 好的写法 vs 不好的写法

```sql
-- 不好：用字符串截取来获取年月
SELECT SUBSTRING(order_date, 1, 4) AS order_year FROM orders;

-- 好：用日期函数
SELECT YEAR(order_date) AS order_year FROM orders;

-- 不好：用字符串比较来算日期范围
SELECT * FROM orders WHERE order_date > '2026-05-01' AND order_date < '2026-05-31';

-- 好：用日期函数
SELECT * FROM orders
WHERE order_date >= DATE_FORMAT(NOW(), '%Y-%m-01')
  AND order_date < DATE_ADD(DATE_FORMAT(NOW(), '%Y-%m-01'), INTERVAL 1 MONTH);
```

### 案例1（基础）：按月统计订单

```sql
SELECT
    DATE_FORMAT(order_date, '%Y-%m') AS order_month,
    COUNT(*) AS order_count,
    SUM(total_amount) AS total_sales
FROM orders
WHERE order_status = 'completed'
GROUP BY DATE_FORMAT(order_date, '%Y-%m')
ORDER BY order_month;
```

**运行结果：**

```text
+-------------+-------------+-------------+
| order_month | order_count | total_sales |
+-------------+-------------+-------------+
| 2026-04     |          15 |    12154.00 |
| 2026-05     |          10 |     6150.00 |
+-------------+-------------+-------------+
```

### 案例2（进阶）：同比环比计算

```sql
-- 环比：本月 vs 上月（使用窗口函数 LAG）
SELECT
    order_month,
    total_sales,
    LAG(total_sales) OVER (ORDER BY order_month) AS last_month_sales,
    ROUND((total_sales - LAG(total_sales) OVER (ORDER BY order_month))
          / LAG(total_sales) OVER (ORDER BY order_month) * 100, 2) AS mom_rate
FROM (
    SELECT strftime('%Y-%m', order_date) AS order_month,
           SUM(total_amount) AS total_sales
    FROM orders
    WHERE order_status = 'completed'
    GROUP BY strftime('%Y-%m', order_date)
) monthly_sales
ORDER BY order_month;
```

**运行结果：**

```text
+-------------+-------------+------------------+----------+
| order_month | total_sales | last_month_sales | mom_rate |
+-------------+-------------+------------------+----------+
| 2026-04     |    12154.00 | NULL             |     NULL |
| 2026-05     |     6150.00 | 12154.00         |  -49.40  |
+-------------+-------------+------------------+----------+
```

> 注：2026-04 没有上一个月（03月）的已完成订单数据，所以 last_month_sales 和 mom_rate 为 NULL。

**教学点 #4**：环比计算推荐使用窗口函数 LAG()，比自连接更简洁高效。

**教学点 #5**：strftime('%Y-%m', date) 是按月统计的标准写法（SQLite），MySQL 使用 DATE_FORMAT(date, '%Y-%m')。

**教学点 #6**：同比 = 和去年同期比，环比 = 和上一期比。SQL 里用窗口函数 LAG() 来实现最优雅。

## 7.3 时间序列分析

一句话：按时间维度拆数据，看趋势、看季节性、看异常。

**生活比喻**：

时间序列分析就像看股票K线——你关心的是"随时间变化的趋势"，而不是某个时间点的快照。

### 按日/周/月/季/年统计

```sql
-- 按日统计
SELECT
```

## 7.4 数据透视：行转列

一句话：行转列就是把竖着的数据横过来，一列变多列。

**生活比喻**：

想象一叠竖着放的纸牌，你把它们摊开成一行——每张牌变成了一个位置。行转列就是这个过程：一行行的数据，变成多列展示。

### 核心方法：CASE WHEN + 聚合

```sql
-- 行转列的核心逻辑：
-- 用 CASE WHEN 把不同行映射到不同列
-- 再用聚合函数合并结果

-- 示例：按品类统计不同地区的销售额（行=品类，列=地区）
SELECT
    p.category,
    SUM(CASE WHEN u.region = '华东' THEN oi.subtotal ELSE 0 END) AS east_sales,
    SUM(CASE WHEN u.region = '华北' THEN oi.subtotal ELSE 0 END) AS north_sales,
    SUM(CASE WHEN u.region = '华南' THEN oi.subtotal ELSE 0 END) AS south_sales
FROM orders o
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p ON oi.product_id = p.product_id
JOIN users u ON o.user_id = u.user_id
WHERE o.order_status = 'completed'
GROUP BY p.category
ORDER BY p.category;
```

**运行结果：**

```text
+----------+------------+-------------+-------------+
| category | east_sales | north_sales | south_sales |
+----------+------------+-------------+-------------+
| 个护     |     259.00 |       79.00 |       119.00|
| 数码     |    6897.00 |     10457.00|      2999.00|
| 服装     |    1508.00 |      1599.00|      1287.00|
| 零食     |     138.00 |       159.00|         0.00|
+----------+------------+-------------+-------------+
```

**教学点 #1**：行转列 = CASE WHEN + 聚合函数。CASE WHEN 把每行映射到对应列，聚合函数把多行合并成一行。

**教学点 #2**：为什么用 SUM 而不是 COUNT？因为我们要汇总的是金额（subtotal），不是数量。如果统计用户数，就用 COUNT DISTINCT。

### 好的写法 vs 不好的写法

```sql
-- 不好：用子查询逐列计算（性能差，写法啰嗦）
SELECT
    p.category,
    (SELECT SUM(oi.subtotal) FROM orders o
     JOIN order_items oi ON o.order_id = oi.order_id
     JOIN users u ON o.user_id = u.user_id
     WHERE oi.product_id IN (SELECT product_id FROM products WHERE category = p.category)
     AND u.region = '华东' AND o.order_status = 'completed') AS east_sales,
    (SELECT SUM(oi.subtotal) FROM orders o
     JOIN order_items oi ON o.order_id = oi.order_id
     JOIN users u ON o.user_id = u.user_id
     WHERE oi.product_id IN (SELECT product_id FROM products WHERE category = p.category)
     AND u.region = '华北' AND o.order_status = 'completed') AS north_sales
FROM products p
GROUP BY p.category;

-- 好：CASE WHEN + 聚合（一次扫描搞定，性能好）
SELECT
    p.category,
    SUM(CASE WHEN u.region = '华东' THEN oi.subtotal ELSE 0 END) AS east_sales,
    SUM(CASE WHEN u.region = '华北' THEN oi.subtotal ELSE 0 END) AS north_sales,
    SUM(CASE WHEN u.region = '华南' THEN oi.subtotal ELSE 0 END) AS south_sales
FROM orders o
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p ON oi.product_id = p.product_id
JOIN users u ON o.user_id = u.user_id
WHERE o.order_status = 'completed'
GROUP BY p.category;
```

**教学点 #3**：好的写法只扫描一次表，不好的写法要扫描多次（每个子查询一次），性能差距巨大。

## 7.5 数据透视：列转行

一句话：列转行就是把横着的数据竖起来，多列变一列。

**生活比喻**：

你有一张成绩单，语文、数学、英语三列横着排——列转行就是把它们变成"科目"和"分数"两列竖着排。

### 核心方法：UNION ALL

```sql
-- 列转行：UNION ALL 把多列数据叠成一行行的
SELECT '语文' AS subject, chinese_score AS score FROM scores
UNION ALL
SELECT '数学' AS subject, math_score AS score FROM scores
UNION ALL
SELECT '英语' AS subject, english_score AS score FROM scores;
```

### 好的写法 vs 不好的写法

```sql
-- 不好：UNION（会去重，而且慢）
SELECT category FROM table1
UNION
SELECT category FROM table2;

-- 好：UNION ALL（不去重，速度快）
SELECT category FROM table1
UNION ALL
SELECT category FROM table2;
```

## 7.6 字符串函数

一句话：字符串函数处理文本数据——拼接、截取、替换、去空格。

**生活比喻**：

字符串函数就像文本编辑器里的操作——选中、复制、粘贴、查找替换，只不过用SQL来做。

### 核心字符串函数

```sql
-- 拼接
SELECT CONCAT('订单', order_id, '已支付') AS msg FROM orders;
SELECT CONCAT_WS('-', '2026', '05', '12') AS date_str;  -- 2026-05-12

-- 截取
SELECT SUBSTRING('Hello World', 1, 5);    -- Hello
SELECT SUBSTRING('Hello World', 7);        -- World

-- 替换
SELECT REPLACE('Hello World', 'World', 'SQL');  -- Hello SQL

-- 去空格
SELECT TRIM('  Hello  ');         -- Hello
SELECT LTRIM('  Hello  ');       -- Hello（左边）
SELECT RTRIM('  Hello  ');       --   Hello（右边，保留左空格）

-- 长度
SELECT LENGTH('Hello');           -- 5（字节数）
SELECT CHAR_LENGTH('你好');       -- 2（字符数，中文友好）

-- 大小写
SELECT UPPER('hello');            -- HELLO
SELECT LOWER('HELLO');            -- hello

-- 查找
SELECT LOCATE('World', 'Hello World');  -- 7（位置）
SELECT INSTR('Hello World', 'World');   -- 7

-- 左右填充
SELECT LPAD('123', 5, '0');      -- 00123
SELECT RPAD('ABC', 5, '*');      -- ABC**
```

### 好的写法 vs 不好的写法

```sql
-- 不好：用 LIKE 模糊匹配做精确查找（性能差）
SELECT * FROM users WHERE username LIKE '%admin%';

-- 好：精确匹配
SELECT * FROM users WHERE username = 'admin';

-- 不好：在 WHERE 里用函数（索引失效）
SELECT * FROM users WHERE UPPER(email) = 'TEST@GMAIL.COM';

-- 好：直接比较（让数据库用索引）
SELECT * FROM users WHERE email = 'test@gmail.com';
```


> 注：此结果依赖 CURDATE()（当前日期），last_order_days = DATEDIFF(当天, 最后下单日期)。随运行日期不同，"活跃/沉默/流失"标签可能变化。

**教学点 #15**：LENGTH 算字节数，CHAR_LENGTH 算字符数。中文场景用 CHAR_LENGTH 更准确。

**教学点 #16**：WHERE 里对列用函数会导致索引失效，能避免就避免。

**教学点 #17**：CONCAT_WS 是拼接多个值的利器，比多次 CONCAT 简洁。

## 教学点汇总

| 编号 | 教学点 | 核心要点 |
|------|--------|----------|
| #1 | CASE WHEN 两种形式 | 简单CASE=等值匹配，搜索CASE=条件判断 |
| #2 | CASE WHEN + GROUP BY | 条件分类作为分组依据 |
| #3 | CASE WHEN + 聚合 | 行转列的核心技巧 |
| #4 | DATEDIFF | 只算天数差，月差用DATE_ADD |
| #5 | DATE_FORMAT | 最灵活的日期格式化，%Y-%m按月 |
| #6 | 同比环比 | 自连接 + DATE_ADD实现 |
| #7 | 时间粒度 | 日/周/月/季/年用不同GROUP BY |
| #8 | 累计+移动平均 | SUM OVER + AVG OVER ROWS BETWEEN |
| #9 | 行转列 | CASE WHEN + 聚合，一次扫描 |
| #10 | NULLIF | 防止除零错误 |
| #11 | 列数固定 | SQL不能动态生成列 |
| #12 | UNION ALL | 列转行用UNION ALL，不用UNION |
| #13 | 列转行行数 | 行数×列数=新行数 |
| #14 | 行转列+列转行 | 可组合使用 |
| #15 | LENGTH vs CHAR_LENGTH | 字节vs字符，中文用CHAR_LENGTH |
| #16 | 函数致索引失效 | WHERE里对列用函数要避免 |
| #17 | CONCAT_WS | 多值拼接利器 |
