# 第五阶段：窗口函数 —— SQL 中最强大也最优雅的武器

> 这一阶段是整个 SQL 学习的重中之重。窗口函数让你既能聚合，又不丢失细节——相当于给每一行开一扇窗，看到周围的数据，但不会把行压缩成一行。搞懂它，你就从"会写 SQL"变成"会分析数据"。
>
> **为什么窗口函数这么重要？**
> - 面试必考：排名、累计、环比是高频题
> - 业务核心：用户行为分析、留存率、排行榜都要用它
> - 性能优势：比 GROUP BY + JOIN 的写法快得多
> - 代码优雅：一条 SQL 搞定复杂分析，不用写一堆子查询

## 1. 窗口函数基本概念

一句话：窗口函数就是给每一行开一扇"窗户"，让它能看到周围的数据，但自己那行还在，不会被压缩掉。

**生活比喻**：想象你站在一排人里面。普通聚合就像把所有人摞成一个统计数字——"平均身高1米7"。窗口函数不一样，它让你站在原地，但给你一扇窗，你能看到周围人的信息，还能算出"你附近这几个人"的平均身高，而你自己还是你自己。

**核心语法**：

```sql
窗口函数名() OVER (
    [PARTITION BY 分组列]
    [ORDER BY 排序列]
    [ROWS BETWEEN ... 滑动窗口]
)
```

**与普通聚合的区别**：

| | 普通聚合（GROUP BY） | 窗口函数（OVER） |
|---|---|---|
| 行数 | 多行压成一行 | 行数不变，每行都保留 |
| 结果 | 只能看到聚合值 | 每行能看到自己的值 + 窗口计算值 |
| 用途 | 统计汇总 | 逐行分析（排名、累计、偏移） |

**好的写法 vs 不好的写法**：

| | 写法 | 说明 |
|---|---|---|
| 好的 | 用窗口函数处理排名、累计等问题 | 行数不变，逻辑清晰 |
| 不好 | 用 GROUP BY 后再 JOIN 回原表 | 写法绕，性能差，容易出错 |

**案例1（基础）**：看每个订单的金额和全公司订单总金额

```sql
-- 窗口函数：每行保留，同时算出总额
-- 全部订单总额约 24185 元
SELECT
    order_id,
    amount             AS 订单金额,
    ROUND(SUM(amount) OVER(), 2) AS 全部订单总额
FROM orders
ORDER BY order_id;
```

### 新手常见坑

1. **WHERE 子句里不能直接用窗口函数**
   ```sql
   -- 错误写法：
   SELECT * FROM orders WHERE amount > AVG(amount) OVER();

   -- 正确写法：用子查询包装
   SELECT * FROM (
       SELECT *, AVG(amount) OVER() AS avg_amount FROM orders
   ) t WHERE amount > avg_amount;
   ```

2. **忘记写 OVER()**
   ```sql
   -- 错误：ROW_NUMBER() 缺少 OVER()
   SELECT ROW_NUMBER() FROM orders;  -- 报错！

   -- 正确：必须加 OVER()
   SELECT ROW_NUMBER() OVER(ORDER BY amount) FROM orders;
   ```

3. **PARTITION BY 和 GROUP BY 搞混**
   - PARTITION BY：分组但行数不变
   - GROUP BY：分组后行数压缩
   - 别在窗口函数里用 GROUP BY！

### 面试高频题

**Q：窗口函数和普通聚合函数有什么区别？**

答：
- 普通聚合（GROUP BY）：多行压缩成一行，只能看到聚合结果
- 窗口函数（OVER）：行数不变，每行都能看到原值 + 聚合结果
- 举例：GROUP BY 算全班平均分只有一个结果，窗口函数让每个学生都看到自己分数和班级平均分

---

### 什么时候用 / 什么时候别用

**用：**
- 需要排名、累计、环比等逐行分析
- 需要对比每行和聚合值（如：高于平均分的订单）
- 取每组第一条或最后一条记录

**别用：**
- 只需要统计汇总（用 GROUP BY 更简洁）
- 不需要保留原行数据
- 数据量超百万且没有索引（性能可能差）

## 2. ROW_NUMBER() — 发号码牌

一句话：ROW_NUMBER() 就是给每一行发一个连续的号码牌，1、2、3……不重复、不跳号。

**生活比喻**：排队拿号。你是1号，他是2号，每个人一个号，绝对不会重复。即使两个人分数一样，号码也不一样——先来的号小，后来的号大。

**好的写法 vs 不好的写法**：

| | 写法 | 说明 |
|---|---|---|
| 好的 | ROW_NUMBER() OVER(ORDER BY 列) | 清晰、标准 |
| 不好 | 自己用变量模拟行号 | MySQL老写法，又丑又容易错 |

**案例1（基础）**：给订单按金额从小到大编号

```sql
SELECT
    order_id,
    amount    AS 订单金额,
    ROW_NUMBER() OVER (ORDER BY amount) AS 行号
FROM orders;
```

```text
|        3 |    399.00 |      1 |
|        7 |    499.00 |      2 |
|        1 |    599.00 |      3 |
|       11 |    699.00 |      4 |
|        9 |    799.00 |      5 |
|        5 |    899.00 |      6 |
|       13 |    999.00 |      7 |
|        2 |   1299.00 |      8 |
```

**案例2（进阶/业务场景）**：找出每个用户金额最高的那笔订单

```sql
-- 按 user_id 分组，每组内按 amount 降序编号
-- 取 row_number = 1 的就是每组最高的
SELECT *
FROM (
    SELECT
        order_id,
        user_id,
        amount,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY amount DESC) AS rn
    FROM orders
) t
WHERE rn = 1;
```

```text
（每个用户金额最高的订单）
```

**教学点 #2**：ROW_NUMBER() = 发号码牌，人手一个，绝不重复。适合"取每组第一条"的需求。

---

### 新手常见坑

1. **ROW_NUMBER 和 RANK 分不清**
   - ROW_NUMBER：不管值相不相同，都给不同的号（1, 2, 3, 4...）
   - RANK：相同的值给相同的号，后面跳号（1, 1, 3, 4...）
   - DENSE_RANK：相同的值给相同的号，后面不跳号（1, 1, 2, 3...）

2. **取每组第一条的写法太绕**
   ```sql
   -- 不好的写法：用 GROUP BY + MAX + JOIN
   SELECT o.* FROM orders o
   JOIN (SELECT user_id, MAX(order_date) AS max_date
         FROM orders GROUP BY user_id) t
   ON o.user_id = t.user_id AND o.order_date = t.max_date;

   -- 好的写法：ROW_NUMBER 一步到位
   SELECT * FROM (
       SELECT *, ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY order_date DESC) AS rn
       FROM orders
   ) t WHERE rn = 1;
   ```

3. **ORDER BY 忘了写，结果随机**
   - 不写 ORDER BY，行号分配是随机的（依赖数据库内部排序）
   - 必须明确指定排序规则

---

### 面试高频题

**Q：如何找出每个部门工资最高的员工？**

答：
```sql
SELECT * FROM (
    SELECT *,
           ROW_NUMBER() OVER(PARTITION BY department ORDER BY salary DESC) AS rn
    FROM employees
) t WHERE rn = 1;
```

追问：如果有并列最高怎么办？
- 用 RANK() 或 DENSE_RANK() 代替 ROW_NUMBER()
- 会把并列最高的都找出来

---

### 什么时候用 / 什么时候别用

**用：**
- 取每组第一条记录（如：每个用户最近一次登录）
- 分页需求（如：每页10条，第3页）
- 去重（保留每组一条）

**别用：**
- 需要处理并列情况（用 RANK/DENSE_RANK）
- 只需要简单排序（用 ORDER BY 即可）

## 3. RANK() / DENSE_RANK() — 排名榜

一句话：RANK 和 DENSE_RANK 也是排名，但跟 ROW_NUMBER 不同——它们允许"并列"。

**生活比喻**：
- ROW_NUMBER = 银行取号，1号2号3号，不重复
- RANK = 运动会排名，两人并列第一，下一个是第三名（1、1、3）
- DENSE_RANK = 也是排名，但并列第一后不跳号（1、1、2）

三者的区别，一张表说清楚：

| 金额 | ROW_NUMBER | RANK | DENSE_RANK |

**好的写法 vs 不好的写法**：

| 好的 | 用 RANK/DENSE_RANK 处理并列 | 语义清晰，自动处理并列 |

### 新手常见坑

1. **RANK 和 DENSE_RANK 分不清**
   - RANK：并列后跳号（1, 1, 3, 4...）→ 适合竞赛排名
   - DENSE_RANK：并列后不跳号（1, 1, 2, 3...）→ 适合计算名次数量

2. **以为 ROW_NUMBER 能处理并列**
   - ROW_NUMBER 永远不并列，即使值相同也给不同号
   - 需要并列就用 RANK 或 DENSE_RANK

3. **排名函数忘记 ORDER BY**

   ```sql
   -- 错误：没有排序依据，排名无意义
   SELECT RANK() OVER() FROM orders;

   SELECT RANK() OVER(ORDER BY amount DESC) FROM orders;
   ```

- RANK：并列跳号，适合竞赛排名

**用 RANK：**
- 竞赛排名（并列第一后下一个是第三）
- 需要跳号效果

**用 DENSE_RANK：**
- 梯队分析（第一梯队、第二梯队...）
- 统计共有几个名次
- 允许并列但不跳号

**用 ROW_NUMBER：**
- 需要唯一编号
- 取每组固定数量记录
- 分页场景

## 4. LAG() / LEAD() — 后视镜和前挡风

一句话：LAG 往后看（看上一行），LEAD 往前看（看下一行）。就像开车的后视镜和前挡风玻璃。

**生活比喻**：
- LAG = 后视镜，看后面那辆车（上一行）
- LEAD = 前挡风，看前面那辆车（下一行）
- 用途：算环比增长、看前后变化

**好的写法 vs 不好的写法**：

| | 写法 | 说明 |
|---|---|---|
| 好的 | LAG/LEAD 取前后行 | 一步到位，性能好 |
| 不好 | 用自连接取前后行 | SQL 又长又慢 |

**案例1（基础）**：看每个订单和上一个订单的金额差

```sql
SELECT
    order_id,
    amount                    AS 当前金额,
    LAG(amount) OVER (ORDER BY order_date) AS 上一个金额,
    amount - LAG(amount) OVER (ORDER BY order_date) AS 金额差
FROM orders;
```

### 新手常见坑

1. **LAG/LEAD 的第二、三个参数搞不清楚**
   ```sql
   LAG(列名, 偏移量, 默认值)

   -- 例：看上上单金额，没有则返回0
   LAG(amount, 2, 0) OVER(ORDER BY order_date)
   ```

2. **ORDER BY 忘了写，LAG/LEAD 没意义**
   - LAG/LEAD 必须知道"上一行"是谁
   - 没有排序，"上一行"是随机的

3. **第一个值 LAG 返回 NULL，忘了处理**
   ```sql
   -- 处理 NULL 的两种方法：
   -- 方法1：用 COALESCE
   COALESCE(LAG(amount) OVER(ORDER BY date), 0)

   -- 方法2：用 NULLIF 配合计算
   (amount - LAG(amount) OVER(ORDER BY date))
   / NULLIF(LAG(amount) OVER(ORDER BY date), 0)
   ```

4. **环比和同比分不清**
   - 环比：和上期比（LAG 偏移1）
   - 同比：和去年同期比（LAG 偏移12或365）

```sql
    date,
```

```sql
        (amount - LAG(amount, 365) OVER(ORDER BY date))
        / NULLIF(LAG(amount, 365) OVER(ORDER BY date), 0) * 100,

    ) AS 同比增长率
FROM daily_sales;
```

## 5. PARTITION BY — 分赛道

一句话：PARTITION BY 就是"分赛道"，让窗口函数在每个赛道里面各自计算，互不干扰。

**生活比喻**：PARTITION BY = 分赛道跑步。100米短跑和400米长跑各跑各的，不在一条道上。每个赛道里自己排名，不影响别的赛道。

**关键理解**：PARTITION BY 和 GROUP BY 的区别——
- GROUP BY：把多行压成一行（压缩）
- PARTITION BY：只是分组，行数不变（不压缩）

**好的写法 vs 不好的写法**：

| | 写法 | 说明 |
|---|---|---|
| 好的 | PARTITION BY 分组后窗口函数各自计算 | 行数不变，每组独立 |
| 不好 | 多次 GROUP BY 再 JOIN | 写法冗长，容易出错 |

**案例1（基础）**：每个分类里按价格排名

```sql
SELECT
    product_name  AS 商品名称,
    category      AS 分类,
    price         AS 价格,
    ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC) AS 分类内排名
FROM products;
```

**运行结果：**

```text
+------------+--------+-----------+------------+
| 商品名称    | 分类   | 价格       | 分类内排名  |
+------------+--------+-----------+------------+
| iPhone 15 Pro| 手机  |   8999.00 |          1 |
| 华为Mate60 | 手机   |   5999.00 |          2 |
| 小米14     | 手机   |   3999.00 |          3 |
| MacBook Air| 电脑   |   7999.00 |          1 |
| 联想笔记本 | 电脑   |   5499.00 |          2 |
| iPad Pro   | 平板   |   6999.00 |          1 |
| 戴尔显示器 | 配件   |   1999.00 |          1 |
| AirPods Pro| 配件   |   1899.00 |          2 |
| 机械键盘   | 配件   |    599.00 |          3 |
| Apple Watch| 手表   |   2999.00 |          1 |
+------------+--------+-----------+------------+
（每个分类内按价格降序排名）
```

**教学点 #5**：PARTITION BY = 分赛道，每组独立计算，行数不压缩。跟 ORDER BY 搭配，就是"每组里面排序"。

---

### 新手常见坑

1. **PARTITION BY 和 GROUP BY 用混了**
   ```sql
   -- 错误：混用
   SELECT user_id, ROW_NUMBER() OVER(GROUP BY user_id)

   -- 正确：PARTITION BY
   SELECT user_id, ROW_NUMBER() OVER(PARTITION BY user_id)
   ```

2. **多个 PARTITION BY**
   - 不可能！一个窗口函数只能有一个 PARTITION BY
   - 多个分组字段用逗号分隔：`PARTITION BY 字段1, 字段2`

3. **PARTITION BY 不加 ORDER BY 的默认行为**
   - 不加 ORDER BY：窗口是整个分组
   - 加 ORDER BY：窗口是"从第一行到当前行"

### 面试高频题

**Q：PARTITION BY 和 GROUP BY 有什么区别？**

答：
| 特性 | PARTITION BY | GROUP BY |
|------|--------------|----------|
| 行数 | 不变 | 压缩 |
| 聚合函数 | 可用 | 可用 |
| 原始列 | 可访问 | 不可访问（非分组列） |
| 用途 | 逐行分析 | 统计汇总 |

**Q：如何找出每个部门薪资前3名的员工？**

答：
```sql
SELECT * FROM (
    SELECT *,
           ROW_NUMBER() OVER(PARTITION BY department ORDER BY salary DESC) AS rn
    FROM employees
) t WHERE rn <= 3;
```

---

### 什么时候用 / 什么时候别用

**用：**
- 每组独立计算（如：每个部门的排名）
- 需要对比组内数据（如：高于部门平均薪资）
- 分组累计（如：每个用户的累计消费）

**别用：**
- 只需要统计汇总（用 GROUP BY）
- 不需要分组（不用 PARTITION BY）

## 6. 窗口聚合（SUM / AVG / COUNT / MAX / MIN OVER）

一句话：普通聚合函数加上 OVER()，就变成了窗口聚合——不压缩行数，每行都能看到聚合结果。

**生活比喻**：普通聚合是"全班的平均分贴在黑板上，每个人看到的都是同一个数"。窗口聚合是"每个人桌上贴着自己小组的平均分"，组不同，看到的数就不同，但人还是那些人，一个都没少。

**好的写法 vs 不好的写法**：

| | 写法 | 说明 |
|---|---|---|
| 好的 | 窗口聚合，行数不变 | 一条 SQL 搞定 |
| 不好 | GROUP BY 聚合后再 JOIN 回去 | 写法绕，容易漏行 |

**案例1（基础）**：每个分类的商品数量和平均价格

```sql
SELECT
    product_name AS 商品名称,
```

### 新手常见坑

   ```sql
       AVG(price) OVER(PARTITION BY category),
       SUM(price) OVER(PARTITION BY category)

       COUNT(*) OVER w,
       AVG(price) OVER w,
       SUM(price) OVER w
   FROM products
   WINDOW w AS (PARTITION BY category);
   ```

   - 不写 PARTITION BY：窗口是全部数据
   - 写 PARTITION BY：窗口是指定分组

## 7. ROWS BETWEEN 滑动窗口 — 卷帘门

一句话：ROWS BETWEEN 指定窗口的"起止范围"，就像卷帘门——拉到哪里算哪里。

**生活比喻**：
- ROWS BETWEEN = 卷帘门，拉到哪看到哪
- 累计求和 = 门从最上面慢慢放下来，越拉越长
- 移动平均 = 固定宽度的一扇窗，滑来滑去

**ROWS BETWEEN 语法**：

```sql
ROWS BETWEEN 起始行 AND 结束行

-- 起始行/结束行的写法：
-- UNBOUNDED PRECEDING  -- 从第一行开始
-- N PRECEDING          -- 往前N行
-- CURRENT ROW          -- 当前行
-- N FOLLOWING          -- 往后N行
-- UNBOUNDED FOLLOWING  -- 到最后一行
```

**常见的滑动窗口模式**：

| 需求 | 写法 |
|------|------|
| 累计求和 | ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW |
| 移动平均（3期） | ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING |
| 到当前为止 | ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW |

**好的写法 vs 不好的写法**：

| | 写法 | 说明 |
|---|---|---|
| 好的 | ROWS BETWEEN 精确控制范围 | 灵活、性能好 |
| 不好 | 不用 ROWS BETWEEN，窗口范围靠猜 | 结果不确定 |

**案例1（基础）**：累计求和——每个月的订单金额累计

```sql
FROM orders
ORDER BY order_date;
```

### 新手常见坑

1. **ROWS 和 RANGE 分不清**
   - ROWS：按物理行数
   - RANGE：按值范围（适合处理重复值）
   ```sql
   -- ROWS：固定行数
   ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING

   -- RANGE：值相同的都算进来
   RANGE BETWEEN 100 PRECEDING AND 100 FOLLOWING
   ```

2. **ORDER BY 不加，ROWS BETWEEN 没意义**
   - 没有顺序，"上一行"、"下一行"没有意义
   - 必须配合 ORDER BY 使用

3. **默认窗口范围**
   - 有 ORDER BY：`ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`
   - 无 ORDER BY：`ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`

4. **ROWS BETWEEN 超出边界**
   - 超出边界会自动截断，不会报错
   - 例如第一行向前取1行，结果是空

## 8. FIRST_VALUE / LAST_VALUE — 每组的第一个和最后一个

一句话：FIRST_VALUE 取窗口里的第一个值，LAST_VALUE 取最后一个值。

**生活比喻**：FIRST_VALUE = 排队第一个人，LAST_VALUE = 排队最后一个人。但注意，LAST_VALUE 有坑——窗口范围默认是"到当前行为止"，所以"最后"其实是"当前行之前的最后一个"。

**好的写法 vs 不好的写法**：

| | 写法 | 说明 |
|---|---|---|
| 好的 | FIRST_VALUE + LAST_VALUE | 语义明确 |
| 不好 | 用 MIN/MAX 代替 LAST_VALUE | 逻辑不同，结果可能错 |

## 9. NTILE() — 分桶函数

一句话：NTILE(N) 把数据切成 N 等份，每份一个桶号。就像把一叠扑克牌分成几堆。

**生活比喻**：NTILE(4) = 把100个人分成4组，每组25人。如果除不尽，前面的组多分一个人。第一组叫1号桶，第二组叫2号桶……

**好的写法 vs 不好的写法**：

| | 写法 | 说明 |
|---|---|---|
| 好的 | NTILE(N) 分桶 | 简洁、标准 |
| 不好 | 手动用 CASE WHEN 分组 | 繁琐，不好维护 |

**案例1（基础）**：把商品按价格分成4个档次

```sql
SELECT
    product_name AS 商品名称,
    price        AS 价格,
    NTILE(4) OVER (ORDER BY price) AS 价格档次
FROM products;
```

**运行结果：**

```text
+------------+-----------+----------+
```

**案例2（进阶/业务场景）**：按金额分成3组，看各组的订单数

```sql
-- 先用 NTILE 分桶，再统计每桶的订单数
SELECT
    t.桶号,
    COUNT(*)    AS 订单数,
    MIN(t.amount) AS 桶内最小金额,
    MAX(t.amount) AS 桶内最大金额
FROM (
    SELECT
        order_id,
        amount,
        NTILE(3) OVER (ORDER BY amount) AS 桶号
    FROM orders
) t
GROUP BY t.桶号
ORDER BY t.桶号;
```

### 新手常见坑

1. **NTILE 和 PERCENTILE 分不清**
   - NTILE：固定分成N桶
   - PERCENTILE：按百分比分（如25%、50%、75%分位数）

2. **NTILE 的桶号分布**
   - 如果总数不能被N整除，前面的桶多1个
   - 例如：20个数据分成3桶，分别是7、7、6

3. **NTILE 不加 ORDER BY**
   - 不排序，分桶是随机的
   - 必须指定排序依据

### 面试高频题

**Q：如何用 NTILE 给商品分档次？**

答：
```sql
SELECT
    product_name,
    price,
    NTILE(4) OVER(ORDER BY price) AS 价格档次
FROM products;

-- 档次含义：
-- 1 = 低端（最便宜的25%）
-- 2 = 中低端
-- 3 = 中高端
-- 4 = 高端（最贵的25%）
```

**Q：如何统计各档次的订单数量和金额？**

答：
```sql
SELECT
    t.档次,
    COUNT(*) AS 订单数,
    SUM(t.amount) AS 总金额,
    AVG(t.amount) AS 平均金额
FROM (
    SELECT
        amount,
        NTILE(4) OVER(ORDER BY amount) AS 档次
    FROM orders
) t GROUP BY t.档次;
```

### 真实业务案例：用户分层

**场景**：将用户按消费金额分成4层

```sql
SELECT
    user_id,
    total_amount AS 总消费,
    NTILE(4) OVER(ORDER BY total_amount DESC) AS 消费层级
FROM (
    SELECT user_id, SUM(amount) AS total_amount
    FROM orders
    GROUP BY user_id
) t;

-- 层级含义：
-- 1 = VIP（消费最高的25%）
-- 2 = 高价值用户
-- 3 = 中等用户
-- 4 = 低价值用户（消费最低的25%）
```

**业务洞察**：
- 层级1用户：重点维护，专属服务
- 层级4用户：尝试激活，推送优惠

**用：**
- 用户/商品分层（高价值、中价值、低价值）

- 快速分组统计

**别用：**
- 需要精确分位数（用 PERCENTILE）

## 综合实战：窗口函数全家桶

把所有窗口函数串起来，做一个完整的业务分析。

**需求**：对订单表做全面分析——排名、累计、环比、分桶，一次性搞定。

```sql
SELECT
    -- 基础信息
    o.order_id                                AS 订单ID,
    o.user_id                                 AS 用户ID,
    o.amount                                  AS 订单金额,
    o.order_date                              AS 下单日期,

    -- 排名分析
    RANK() OVER (ORDER BY o.amount DESC)      AS 全局金额排名,
    DENSE_RANK() OVER (ORDER BY o.amount DESC) AS 全局紧凑排名,

    -- 分组排名
    ROW_NUMBER() OVER (
        PARTITION BY o.user_id ORDER BY o.amount DESC
    ) AS 用户内金额排名,

    -- 窗口聚合
    SUM(o.amount) OVER (PARTITION BY o.user_id)  AS 用户订单总额,
    AVG(o.amount) OVER (PARTITION BY o.user_id)  AS 用户平均金额,

    -- 累计求和
    SUM(o.amount) OVER (
        ORDER BY o.order_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS 累计金额,

    -- 移动平均
    ROUND(AVG(o.amount) OVER (
        ORDER BY o.order_date
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ), 2) AS 三期移动平均,

    -- 偏移函数
    LAG(o.amount) OVER (ORDER BY o.order_date)  AS 上一单金额,
    LEAD(o.amount) OVER (ORDER BY o.order_date) AS 下一单金额,

    -- 分桶
    NTILE(4) OVER (ORDER BY o.amount)         AS 金额四分位

FROM orders o
ORDER BY o.order_date;
```

## 知识点速查表

| 窗口函数 | 比喻 | 用途 |
|---------|------|------|
| ROW_NUMBER() | 发号码牌 | 逐行编号，取每组第一条 |
| RANK() | 排名榜（跳号） | 并列排名，跳号 |
| DENSE_RANK() | 排名榜（不跳号） | 并列排名，紧凑 |
| LAG() | 后视镜 | 看上一行 |
| LEAD() | 前挡风 | 看下一行 |
| SUM/AVG/COUNT/MAX/MIN OVER | 不压缩的聚合 | 每行都有聚合值 |
| ROWS BETWEEN | 卷帘门 | 累计求和、移动平均 |
| FIRST_VALUE | 排队第一个人 | 窗口第一个值 |
| LAST_VALUE | 排队最后一个人 | 窗口最后一个值（有坑！） |
| NTILE() | 分桶 | 把数据切成N等份 |

## 窗口函数选择决策指南

**需求：排名相关**
- 只需要唯一编号 → **ROW_NUMBER()**
- 允许并列，并列后跳号 → **RANK()**
- 允许并列，并列后不跳号 → **DENSE_RANK()**

**需求：前后对比**
- 看上一行 → **LAG()**
- 看下一行 → **LEAD()**
- 环比增长 → **LAG() + 计算**

**需求：聚合对比**
- 看每行的聚合值 → **SUM/AVG/COUNT/MAX/MIN OVER()**
- 分组聚合 → **加上 PARTITION BY**

**需求：累计/移动**
- 累计求和 → **SUM() OVER(ORDER BY 列)**（默认就是累计）
- 移动平均 → **AVG() OVER(ORDER BY 列 ROWS BETWEEN N PRECEDING AND CURRENT ROW)**
- 分组累计 → **加上 PARTITION BY**

**需求：首末值**
- 每组第一个 → **FIRST_VALUE()**
- 每组最后一个 → **LAST_VALUE() + ROWS BETWEEN**

**需求：分层分桶**
- 固定分N层 → **NTILE(N)**

## 性能优化建议

### 1. 索引是关键

窗口函数依赖排序，索引直接影响性能：

```sql
-- 窗口函数查询
SELECT *, ROW_NUMBER() OVER(ORDER BY order_date) FROM orders;

-- 性能优化：给排序字段加索引
CREATE INDEX idx_order_date ON orders(order_date);
```

### 2. 避免重复计算

多个窗口函数用相同窗口时，用 WINDOW 子句：

```sql
-- 不好：重复写窗口定义
SELECT
    ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY order_date),
    RANK() OVER(PARTITION BY user_id ORDER BY order_date),
    DENSE_RANK() OVER(PARTITION BY user_id ORDER BY order_date)
FROM orders;

-- 好：窗口别名（MySQL 8.0+）
SELECT
    ROW_NUMBER() OVER w,
    RANK() OVER w,
    DENSE_RANK() OVER w
FROM orders
WINDOW w AS (PARTITION BY user_id ORDER BY order_date);
```

### 3. 减少窗口大小

窗口越大，计算越慢：

```sql
-- 慢：大窗口
SUM(amount) OVER(PARTITION BY category)

-- 快：小窗口（如果业务允许）
SUM(amount) OVER(
    PARTITION BY category
    ORDER BY date
    ROWS BETWEEN 30 PRECEDING AND CURRENT ROW
)
```

### 4. PARTITION BY 字段要有索引

```sql
-- 窗口函数
SELECT *, COUNT(*) OVER(PARTITION BY user_id) FROM orders;

-- 性能优化：给分区字段加索引
CREATE INDEX idx_user_id ON orders(user_id);
```

### 5. 大数据量考虑分批

百万级数据，窗口函数可能很慢：

```sql
-- 方案1：先过滤再计算
SELECT *, ROW_NUMBER() OVER(ORDER BY amount DESC)
FROM orders
WHERE order_date >= '2024-01-01';  -- 先缩小范围

-- 方案2：用临时表
CREATE TEMPORARY TABLE temp_orders AS
SELECT * FROM orders WHERE order_date >= '2024-01-01';

SELECT *, ROW_NUMBER() OVER(ORDER BY amount DESC)
FROM temp_orders;
```

## 更多实战案例

### 案例1：留存率计算

**场景**：计算次日留存、7日留存、30日留存

```sql
-- 步骤1：找出每个用户的首次登录日期
WITH first_login AS (
    SELECT
        user_id,
        MIN(login_date) AS first_date
    FROM user_login
    GROUP BY user_id
),

-- 步骤2：计算首次登录后第N天是否登录
retention AS (
    SELECT
        f.first_date,
        f.user_id,
        MAX(CASE WHEN DATEDIFF(l.login_date, f.first_date) = 1 THEN 1 ELSE 0 END) AS 次日留存,
        MAX(CASE WHEN DATEDIFF(l.login_date, f.first_date) = 7 THEN 1 ELSE 0 END) AS 七日留存,
        MAX(CASE WHEN DATEDIFF(l.login_date, f.first_date) = 30 THEN 1 ELSE 0 END) AS 三十日留存
    FROM first_login f
    LEFT JOIN user_login l ON f.user_id = l.user_id
    GROUP BY f.first_date, f.user_id
)

-- 步骤3：汇总各批次的留存率
SELECT
    first_date AS 注册日期,
    COUNT(*) AS 新增用户数,
    SUM(次日留存) AS 次日留存数,
    ROUND(SUM(次日留存) / COUNT(*) * 100, 2) AS 次日留存率,
    SUM(七日留存) AS 七日留存数,
    ROUND(SUM(七日留存) / COUNT(*) * 100, 2) AS 七日留存率,
    SUM(三十日留存) AS 三十日留存数,
    ROUND(SUM(三十日留存) / COUNT(*) * 100, 2) AS 三十日留存率
FROM retention
GROUP BY first_date
ORDER BY first_date;
```

### 案例2：连续登录天数

**场景**：计算每个用户的最大连续登录天数

```sql
-- 核心思路：用 ROW_NUMBER 标记登录序号，日期减序号相同的是连续的
WITH login_with_seq AS (
    SELECT
        user_id,
        login_date,
        ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY login_date) AS seq
    FROM user_login
),

-- 日期减序号，连续登录的结果相同
login_groups AS (
    SELECT
        user_id,
        login_date,
        DATE_SUB(login_date, INTERVAL seq DAY) AS group_key
    FROM login_with_seq
)

-- 统计每个用户的最大连续天数
SELECT
    user_id,
    MAX(连续天数) AS 最大连续登录天数
FROM (
    SELECT
        user_id,
        group_key,
        COUNT(*) AS 连续天数
    FROM login_groups
    GROUP BY user_id, group_key
) t
GROUP BY user_id
ORDER BY 最大连续登录天数 DESC;
```

### 案例3：Top N 问题

**场景**：找出每个分类销量前3的商品

```sql
-- 方法1：ROW_NUMBER（允许并列选一个）
SELECT * FROM (
    SELECT
        p.category,
        p.product_name,
        COUNT(*) AS 销量,
        ROW_NUMBER() OVER(PARTITION BY p.category ORDER BY COUNT(*) DESC) AS rn
    FROM orders o
    JOIN products p ON o.product_id = p.product_id
    GROUP BY p.category, p.product_name
) t WHERE rn <= 3;

-- 方法2：DENSE_RANK（允许并列，可能超过3个）
SELECT * FROM (
    SELECT
        p.category,
        p.product_name,
        COUNT(*) AS 销量,
        DENSE_RANK() OVER(PARTITION BY p.category ORDER BY COUNT(*) DESC) AS ranking
    FROM orders o
    JOIN products p ON o.product_id = p.product_id
    GROUP BY p.category, p.product_name
) t WHERE ranking <= 3;
```

### 案例4：同比环比分析

**场景**：月度销售额的同比、环比分析

```sql
WITH monthly_sales AS (
    SELECT
        DATE_FORMAT(order_date, '%Y-%m') AS 月份,
        SUM(amount) AS 销售额
    FROM orders
    GROUP BY DATE_FORMAT(order_date, '%Y-%m')
)

SELECT
    月份,
    销售额,
    -- 环比（和上个月比）
    LAG(销售额) OVER(ORDER BY 月份) AS 上月销售额,
    ROUND(
        (销售额 - LAG(销售额) OVER(ORDER BY 月份))
        / NULLIF(LAG(销售额) OVER(ORDER BY 月份), 0) * 100,
        2
    ) AS 环比增长率,
    -- 同比（和去年同期比）
    LAG(销售额, 12) OVER(ORDER BY 月份) AS 去年同期销售额,
    ROUND(
        (销售额 - LAG(销售额, 12) OVER(ORDER BY 月份))
        / NULLIF(LAG(销售额, 12) OVER(ORDER BY 月份), 0) * 100,
        2
    ) AS 同比增长率
FROM monthly_sales;
```

## 总结：窗口函数是 SQL 分析的核心武器

**核心要点**：
1. 窗口函数 = 聚合但不压缩行数
2. 三大排名函数：ROW_NUMBER（不并列）、RANK（并列跳号）、DENSE_RANK（并列不跳号）
3. LAG/LEAD = 前后对比，算环比、看趋势
4. PARTITION BY = 分组，ROWS BETWEEN = 窗口范围
5. FIRST_VALUE/LAST_VALUE = 首末值，注意 LAST_VALUE 的坑
6. NTILE = 分桶，用户分层、商品分层

**记忆口诀**：
- ROW_NUMBER 发号码，人手一个不重复
- RANK 排名会跳号，DENSE_RANK 不跳号
- LAG 后视镜，LEAD 前挡风
- PARTITION BY 分赛道，ROWS BETWEEN 卷帘门
- FIRST 取第一个，LAST 取最后一个（记得加范围）
