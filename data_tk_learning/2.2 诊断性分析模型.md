# 2.2 诊断性分析模型 —— "为什么发生"

> 诊断性分析是描述性分析的进阶——只知道"发生了什么"还不够，必须追问"为什么发生"，才能对症下药。学完这章，你能精准定位问题的根本原因。

**学完这章你能干啥？**
- 能用 5 Whys 方法追问问题的根本原因
- 能用维度拆解定位异常的具体来源
- 能量化各因素对问题的贡献度
- 避免"相关当因果"等常见误区

---

## 一、什么是诊断性分析？

### 1.1 用生活例子理解

**用生活例子理解**：

就像医生看病——描述性分析告诉你"发烧了"（症状），诊断性分析要找出"是病毒感染还是细菌感染"（病因），只有找到病因，才能对症下药。

**代码示例**：

```python
# 描述性分析：只知道"发生了什么"
利润变化 = -20
print(f"利润下降了 {利润变化}%")  # 知道了，但不知道为什么

# 诊断性分析：追问"为什么发生"
原因分析 = {
    "原材料成本上涨": 35,
    "销量下降": 10,
    "促销费用增加": 5
}
print("根本原因：原材料成本上涨 35%")
print("建议：更换供应商或优化采购策略")
```

**专业术语**：

诊断性分析（Diagnostic Analysis）是在描述性分析的基础上，运用因果推断方法，识别业务异常的根本原因，回答"为什么会这样"的分析方法。

### 1.2 分析进阶路径

| 分析层次 | 回答的问题 | 生活类比 | 医疗场景对应 |
|---------|-----------|---------|-------------|
| 描述性 | 发生了什么？ | 体温计显示 38.5°C | 症状描述 |
| **诊断性** | **为什么发生？** | **验血发现是病毒感染** | **病因诊断** |
| 预测性 | 将来会怎样？ | 预判不治疗会加重 | 病情预判 |
| 处方性 | 该怎么做？ | 开抗病毒药物 | 治疗方案 |

### 1.3 诊断性分析的三大工具

| 工具 | 核心逻辑 | 适用场景 | 生活类比 |
|------|----------|----------|----------|
| **5 Whys** | 连续追问找根因 | 单一问题的深挖 | 像剥洋葱，一层层剥到核心 |
| **鱼骨图** | 多维度系统性排查 | 复杂问题的全景扫描 | 像侦探的线索墙，全面排查 |
| **异常归因** | 量化各因素贡献 | 数据波动的精确拆解 | 像分账单，算清谁该付多少 |

**工具选择指南**：

| 问题类型 | 推荐工具 | 使用方法 |
|---------|---------|---------|
| 单一明确问题 | 5 Whys | 直接追问，快速定位根因 |
| 复杂多因素问题 | 鱼骨图 + 5 Whys | 先鱼骨图扫描，再 5 Whys 深挖 |
| 需要量化贡献度 | 异常归因 | 精确计算各因素权重 |

## 二、诊断分析五步法

### 2.1 五步法总览

| 步骤 | 核心任务 | 关键问题 | 输出成果 |
|:----:|:--------:|:--------:|:--------:|
| **Step 1** | 确认异常 | 是真异常还是正常波动？ | 异常确认报告 |
| **Step 2** | 维度拆解 | 异常来自哪个维度？ | 异常来源定位 |
| **Step 3** | 构建假设 | 可能的原因有哪些？ | 假设清单 |
| **Step 4** | 验证假设 | 哪个假设有数据支撑？ | 假设验证结果 |
| **Step 5** | 量化归因 | 各因素贡献多少？ | 归因权重表 |

### 2.2 Step 1：确认异常是否真实

**用生活例子理解**：

就像体检时医生判断你的指标是否异常——不能只看一次血压高就判定高血压，要看长期趋势和统计范围。

**异常判定方法**：

| 方法 | 适用场景 | 判定标准 | 生活类比 |
|------|----------|----------|----------|
| **3σ原则** | 近似正态分布 | 超出均值±3σ | 身高超过平均值3个标准差 |
| **IQR法** | 偏态分布 | <Q1-1.5×IQR 或 >Q3+1.5×IQR | 收入分布中极端富裕人群 |
| **业务规则** | 有业务经验 | 超出历史波动范围 | 销量低于去年同期 |
| **同比对比** | 季节性业务 | 与去年同期差异 | 冰激凌销量看去年同月 |

```python
# 3σ 异常判定示例
历史数据 = [11.2, 11.5, 11.8, 12.0, 12.3, 12.1, 12.0]
当前值 = 9.5

均值 = sum(历史数据) / len(历史数据)  # 11.84
标准差 = 0.38  # 假设计算结果
下界 = 均值 - 3 * 标准差  # 10.70

if 当前值 < 下界:
    print(f"当前值 {当前值} < 下界 {下界}")
    print("结论：超出 3σ 范围，确认为统计异常")
else:
    print("结论：在正常波动范围内")
```

### 2.3 Step 2：维度拆解定位

**用生活例子理解**：

就像医生做检查——不能只说"身体不舒服"，要分系统检查（消化系统、呼吸系统、神经系统），找到具体哪个器官出了问题。

**拆解顺序**：先粗后细，先大后小

```python
# 维度拆解示例：订单量骤降
总下降 = 2.5万  # 从 12万 → 9.5万

# 第一轮：按城市拆解
城市影响 = {
    "北京": -0.1万,
    "上海": -0.1万,
    "广州": -0.1万,
    "深圳": -0.1万,
    "成都": -0.8万,  # 最大异常！
    "其他": 0
}

print("第一轮拆解发现：成都贡献了 -0.8万（占总量下降的 32%）")

# 第二轮：按时段拆解
时段影响 = {
    "早餐": -0.1万,
    "午餐": -0.7万,
    "晚餐": -1.1万,  # 重灾区
    "夜宵": -0.4万   # 重灾区
}

print("第二轮拆解发现：晚餐和夜宵下降最严重")
```

**维度拆解表**：

| 城市 | 上周日均 | 本周日均 | 变化 | 对总量的影响 |
|------|---------|---------|------|-------------|
| 北京 | 3.2万 | 3.1万 | -3.1% | -0.1万 |
| 上海 | 2.8万 | 2.7万 | -3.6% | -0.1万 |
| 成都 | 1.2万 | 0.4万 | **-66.7%** | **-0.8万** |
| 其他 | 4.8万 | 6.3万 | +31.3% | +1.5万 |

### 2.4 Step 3：构建因果假设

**用生活例子理解**：

就像医生根据症状列出可能的疾病清单——发烧可能是感冒、流感、肺炎，需要进一步检查才能确诊。

**提出至少 3 个可能的假设**，避免过早锁定：

```python
# 假设构建示例
假设清单 = [
    {"假设": "天气因素", "验证方法": "查气象数据，对比历史天气相似期"},
    {"假设": "竞品动作", "验证方法": "查竞品活动数据，监控竞品动态"},
    {"假设": "内部故障", "验证方法": "查系统日志，排查技术问题"},
    {"假设": "政策变化", "验证方法": "查政策公告，对比受限区域"}
]

print("构建假设清单：")
for i, 假设 in enumerate(假设清单, 1):
    print(f"假设{i}：{假设['假设']} → {假设['验证方法']}")
```

### 2.5 Step 4：用数据验证假设

**用生活例子理解**：

就像医生开检查单——怀疑是病毒感染就验血，怀疑是肺炎就拍CT，根据检查结果确诊或排除。

```python
# 假设验证示例
验证结果 = {
    "天气因素": {"数据": "相似天气时订单也下降 15%", "结论": "确认"},
    "竞品动作": {"数据": "竞品补贴 +30%，影响约 12%", "结论": "部分确认"},
    "内部故障": {"数据": "无异常错误", "结论": "排除"},
    "政策变化": {"数据": "限行后成都下降 67%", "结论": "确认"}
}

print("假设验证结果：")
for 假设, 结果 in 验证结果.items():
    print(f"{假设}：{结果['结论']} ← {结果['数据']}")
```

**假设验证表**：

| 假设 | 验证方法 | 数据支撑 | 结论 |
|------|----------|----------|------|
| 天气因素 | 对比同天气历史数据 | 相似天气时订单下降 15% | ✅ 确认 |
| 竞品动作 | 监测竞品补贴力度 | 竞品补贴 +30%，影响 12% | ✅ 部分确认 |
| 内部故障 | 系统错误日志 | 无异常错误 | ❌ 排除 |
| 政策变化 | 成都政策公告+限行数据 | 限行后成都下降 67% | ✅ 确认 |

### 2.6 Step 5：量化各因素贡献

**用生活例子理解**：

就像破案后确定每个嫌疑人的责任比例——主犯承担主要责任，从犯承担次要责任，实现罪责相当。

```python
# 影响贡献计算
影响因素 = {
    "成都限行政策": {"影响": -0.8万, "占比": 32},
    "恶劣天气→运力不足": {"影响": -0.7万, "占比": 28},
    "配送超时→用户取消": {"影响": -0.5万, "占比": 20},
    "竞品补贴分流": {"影响": -0.3万, "占比": 12},
    "其他因素": {"影响": -0.2万, "占比": 8}
}

print("归因结果：")
for 因素, 数据 in 影响因素.items():
    print(f"{因素}：{数据['影响']}万/日，占比 {数据['占比']}%")
```

**归因结果表**：

| 原因 | 影响订单量（万/日） | 占比 | 可控性 | 优先级 |
|------|-------------------|------|--------|:------:|
| 成都限行政策 | -0.8 | 32% | 不可控，但可应对 | ⭐⭐ |
| 恶劣天气→运力不足 | -0.7 | 28% | 部分可控 | ⭐⭐⭐ |
| 配送超时→用户取消 | -0.5 | 20% | 可控 | ⭐⭐⭐⭐ |
| 竞品补贴分流 | -0.3 | 12% | 可应对 | ⭐⭐ |
| 其他因素 | -0.2 | 8% | — | ⭐ |

## 三、5 Whys 方法详解

### 3.1 用生活例子理解

**用生活例子理解**：

就像剥洋葱——表面看到的是症状（洋葱外皮），一层层剥开才能看到核心（根因）。每问一次"为什么"，就剥开一层。

### 3.2 5 Whys 追问流程

```python
# 5 Whys 追问示例：订单量骤降
问题链 = [
    {"层级": "表象", "问题": "订单量下降 20.8%", "原因": "成都暴跌 + 晚餐夜宵下降"},
    {"层级": "Why 1", "问题": "成都为何暴跌？", "原因": "骑手限行政策"},
    {"层级": "Why 2", "问题": "晚餐夜宵为何下降？", "原因": "恶劣天气 + 运力不足"},
    {"层级": "Why 3", "问题": "运力为何不足？", "原因": "配送时长增加 77%"},
    {"层级": "Why 4", "问题": "为何导致订单暴跌？", "原因": "超时率飙升，用户大量取消"},
    {"层级": "Why 5", "问题": "为何没有预警？", "原因": "系统未接入气象数据 + 政策监控缺失"}
]

print("5 Whys 追问链：")
for 链 in 问题链:
    print(f"{链['层级']}：{链['问题']} → {链['原因']}")
```

**根因定位表**：

| 层级 | 问题 | 原因 | 是否可行动 | 根因判定 |
|------|------|------|-----------|---------|
| 表象 | 订单量下降 20.8% | 成都暴跌 + 晚餐夜宵下降 | ❌ 太笼统 | 非根因 |
| Why 1 | 成都为何暴跌？ | 骑手限行政策 | ⚠️ 外部因素 | 中间原因 |
| Why 2 | 晚餐夜宵为何下降？ | 恶劣天气 + 运力不足 | ⚠️ 部分可控 | 中间原因 |
| Why 3 | 运力为何不足？ | 配送时长增加 77% | ⚠️ 需继续追问 | 中间原因 |
| Why 4 | 为何导致订单暴跌？ | 超时率飙升，用户大量取消 | ✅ 可优化体验 | 次级根因 |
| **Why 5** | **为何没有预警？** | **系统未接入气象数据 + 政策监控缺失** | **✅ 可系统改进** | **核心根因** |

### 3.3 5 Whys 核心原则

| 原则 | 说明 | 生活类比 |
|------|------|----------|
| 基于事实 | 每次追问都要基于事实，而非猜测 | 医生追问病史要有依据 |
| 问到可行动 | 问到"可采取行动"的层面为止（通常3-5次） | 治疗方案要能执行 |
| 系统性原因 | 避免把责任推给人，要找到系统性原因 | 找制度漏洞，不找个人过错 |
| 多根因 | 同一问题可能有多个根因，需要分别追问 | 多种病因，分别治疗 |

## 四、实战案例：外卖平台订单量骤降

### 4.1 业务背景

> 某外卖平台 2025 年 4 月第 3 周，日均订单量从 12 万单骤降至 9.5 万单（-20.8%）。管理层要求 48 小时内定位原因。

### 4.2 诊断分析过程

```python
# 完整诊断分析示例

# Step 1：确认异常
历史均值 = 11.84
标准差 = 0.38
下界 = 历史均值 - 3 * 标准差  # 10.70
当前值 = 9.5

print("Step 1：确认异常")
print(f"当前值 {当前值} < 下界 {下界}")
print("结论：超出 3σ 范围，确认为统计异常 ✓")

# Step 2：维度拆解
print("\nStep 2：维度拆解")
print("城市维度：成都下降 67%，贡献 -0.8万")
print("时段维度：晚餐下降 31%，夜宵下降 40%")

# Step 3：构建假设
print("\nStep 3：构建假设")
假设 = ["天气因素", "竞品动作", "内部故障", "政策变化"]
print(f"假设清单：{假设}")

# Step 4：验证假设
print("\nStep 4：验证假设")
print("天气因素 → ✅ 确认（相似天气时订单下降 15%）")
print("政策变化 → ✅ 确认（成都限行后下降 67%）")
print("竞品动作 → ✅ 部分确认（竞品补贴 +30%）")
print("内部故障 → ❌ 排除（无异常错误）")

# Step 5：量化归因
print("\nStep 5：量化归因")
归因 = {
    "成都限行": 32,
    "恶劣天气": 28,
    "配送超时": 20,
    "竞品分流": 12,
    "其他": 8
}
for 因素, 占比 in 归因.items():
    print(f"{因素}：{占比}%")
```

### 4.3 根因与对策

```python
# 根因分析结果
根因 = {
    "核心根因": "系统未接入气象数据 + 政策监控缺失",
    "次级根因": "超时率高导致用户取消",
    "外部因素": "政策变化、天气变化"

对策 = {

    "外部因素对策": ["建立应急预案", "调整运力配置"]
}

print("根因分析：")
for 类型, 原因 in 根因.items():
    print(f"{类型}：{原因}")

print("\n对策建议：")
for 类型, 措施 in 对策.items():
    print(f"{类型}：{措施}")
```

## 五、常见误区与纠正

| 误区 | 表现 | 后果 | 纠正方法 | 生活类比 |
|------|------|------|----------|----------|
| 过早锁定原因 | 第一个想到的原因就当做真相 | 误诊误治 | 至少提出 3 个假设逐个验证 | 第一感觉是感冒就按感冒治 |
| 相关当因果 | "A和B相关，所以A导致B" | 错误归因 | 找到因果机制或用实验验证 | 冰激凌销量和溺水相关，但不是因果 |
| 忽略交互效应 | 各因素单独看正常，组合后异常 | 归因不准 | 检查因素间的协同效应 | 单吃药无效，药+运动有效 |
| 停在表层 | "订单下降因为用户少了" | 无法根治 | 继续追问：为什么用户少了？ | 只治标不治本 |
| 确认偏差 | 只找支持自己判断的证据 | 结论片面 | 刻意寻找反面证据 | 只听支持自己观点的医生 |

**误区纠正实例**：

```python
# 误区：相关当因果
错误推理 = "冰淇淋销量↑ 溺亡↑ → 冰淇淋导致溺亡"
问题 = "相关≠因果，实际是夏天导致两者同时增加"

# 纠正
正确推理 = {
    "现象": "冰淇淋销量和溺亡人数正相关",
    "真实原因": "夏天（气温升高）导致两者同时增加",
    "验证方法": "控制气温变量后，相关性消失"
}

print("误区纠正：")
print(f"错误推理：{错误推理}")
print(f"问题：{问题}")
print(f"正确推理：夏天是共同原因，冰淇淋和溺亡不是因果关系")
```

## 六、即时练习

> **题目**：某在线教育平台 3 月完课率从 62% 骤降至 45%，请用诊断分析方法定位原因。

**给到的数据**：
- 课程 A 完课率：68% → 42%（-38%）
- 课程 B 完课率：60% → 58%（-3%）
- 课程 C 完课率：55% → 35%（-36%）
- 课程 A 在 3 月更新了教学视频格式（从 10 分钟/节改为 45 分钟/节）
- 课程 C 在 3 月上线的移动端播放器存在卡顿问题

**参考分析**：

```python
# 诊断分析练习
print("5 Whys 追问：")
问题链 = [
    ("Why 1", "完课率下降", "课程 A 和 C 大幅下降"),
    ("Why 2", "课程 A 下降", "视频时长从 10min 改为 45min"),
    ("Why 3", "改时长后完课率暴跌", "单集太长，用户碎片时间无法看完"),
    ("Why 4", "课程 C 下降", "移动端播放器卡顿"),
    ("Why 5", "卡顿没提前发现", "QA 未覆盖弱网环境测试")
]

for 层级, 问题, 原因 in 问题链:
    print(f"{层级}：{问题} → {原因}")

print("\n归因结果：")
归因 = {"课程 A（视频格式变更）": 60, "课程 C（播放器 bug）": 35, "其他因素": 5}
for 因素, 占比 in 归因.items():
    print(f"{因素}：贡献 {占比}%")

print("\n建议：")
print("课程 A：拆分为 10-15 分钟/节")
print("课程 C：紧急修复播放器")
```

| 内容 | 要点 |
