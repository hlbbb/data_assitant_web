# LTV/CAC 用户生命周期分析项目深度剖析（上）

## 一、课题思路

### LTV/CAC 与 RFM、AARRR 的区别

三大分析框架各有侧重：

- **RFM** 看「分层」——按最近购买时间、购买频率、消费金额把用户分成不同等级，回答「谁是高价值用户」
- **AARRR** 看「漏斗」——从获取、激活、留存、变现、推荐五个环节构建增长模型，回答「增长瓶颈在哪」
- **LTV/CAC** 看「商业健康度」——从用户生命周期价值和获客成本的关系出发，回答「赚的钱够不够覆盖成本」

三者并不互斥，而是互补关系。RFM 是运营层的分析工具，AARRR 是增长层的框架，LTV/CAC 是战略层的评估体系。

### 什么场景必须用 LTV/CAC

以下三种场景，LTV/CAC 是不可替代的分析工具：

1. **融资场景**：投资人最关心的不是 RFM 分了几层，而是你的商业模式到底能不能赚钱。LTV/CAC 直接回答这个问题。
2. **盈利分析**：当企业从「烧钱增长」转向「盈利优先」时，LTV/CAC 是衡量盈利能力的核心指标。
3. **渠道 ROI 评估**：不同渠道的 CAC 差异巨大，结合 LTV 可以评估每个渠道的真实 ROI。

### 本项目的业务假设

本项目基于一个电商平台的真实场景：
- 平台拥有约 3000 用户，15000 笔订单，总收入约 450万元
- 假设 LTV 约 580元，CAC 约 26元，LTV/CAC 约 22
- 用户通过多个渠道获取，渠道成本差异明显
- 用户价值呈长尾分布，可划分为四个层级

## 二、准备工作

### 2.1 数据设计思路

为什么需要 users、transactions、channel_costs 三张表？

**users 表**：存储用户基本信息，包括用户ID、注册日期、渠道来源、城市等级等。这是 LTV 计算的基础——我们需要知道「谁在什么时候来了」。

**transactions 表**：存储交易记录，包括订单ID、用户ID、交易金额、交易日期等。这是 LTV 计算的核心——我们需要知道「每个用户花了多少钱」。

**channel_costs 表**：存储渠道成本，包括渠道名称、月份、成本金额等。这是 CAC 计算的基础——我们需要知道「获取用户花了多少钱」。

三张表的关系：users 通过 user_id 关联 transactions，通过 channel 关联 channel_costs。

**渠道成本表的设计逻辑**：
- 按月记录每个渠道的投放成本
- CAC = 渠道总成本 / 该渠道新增用户数
- 不同渠道的 CAC 差异反映了渠道效率

**用户四档分层**：
- 鲸鱼用户：LTV 最高的头部用户，约15%
- 海豚用户：中高价值用户，约25%
- 小鱼用户：中等价值用户，约35%
- 虾米用户：低价值用户，约25%

### 2.2 技术选型

**同期群分析（Cohort Analysis）的两种实现**：

1. **按注册月份分组**：将用户按注册月份分成同期群，追踪每个同期群的留存和收入。这是最常用的方式。
2. **按首次购买月份分组**：将用户按首次购买月份分组，更关注购买行为而非注册行为。

本项目采用「按注册月份分组」的方式，因为注册是用户生命周期的起点。

**LTV 的三种估算方法**：

1. **历史法**：LTV = 累计收入 / 用户数。简单直观，但只能看过去。
2. **预测法**：基于机器学习模型预测未来收入，再计算 LTV。复杂但前瞻。
3. **留存曲线法**：LTV = ARPU × 留存曲线下面积。兼顾历史和预测，是最推荐的方法。

**本项目使用的方法**：
- 主方法：历史法（LTV = ARPU × 平均生命周期）
- 辅助方法：留存曲线法（用于验证和补充）

### 2.3 避坑指南

**LTV 计算中的时间窗口陷阱**：
- 如果只看1个月的 LTV，会严重低估真实 LTV
- 如果看12个月的 LTV，可能高估短期价值
- 建议：至少看6个月的数据，同时用留存曲线外推

**CAC 分摊的颗粒度问题**：
- 简单 CAC = 总成本 / 总用户数，忽略了渠道差异
- 精确 CAC = 按渠道计算，能反映渠道效率差异
- 建议：必须按渠道计算 CAC，否则无法指导投放决策

**混合毛利率的误导性**：
- 毛利率 ≠ LTV/CAC，毛利率反映产品盈利能力，LTV/CAC 反映用户价值与成本的比值
- 高毛利率不一定意味着高 LTV/CAC（如果 CAC 也很高）
- 建议：两个指标结合使用

## 三、建模详解

### 3.1 LTV 计算

**历史法**：LTV = 累计收入 / 用户数

这是最简单的计算方式。对于 N 个用户和 M 元总收入：
LTV = M / N

**留存曲线法**：LTV = ARPU × 留存曲线下面积

留存曲线描述了用户随时间的留存率变化。曲线下面积就是平均生命周期：
LTV = ARPU × ∫留存率(t)dt

代码逻辑解析：
```python
# 历史法
ltv = total_revenue / total_users

# 留存曲线法
arpu = total_revenue / total_users
retention_curve = compute_retention(tables)
avg_lifetime = np.trapz(retention_curve)  # 曲线下面积
ltv = arpu * avg_lifetime
```

### 3.2 CAC 计算

**简单法 vs 精确法**：
- 简单法：CAC = 总获客成本 / 总新用户数
- 精确法：CAC_channel = 渠道总成本 / 渠道新用户数

**渠道 CAC 的归因问题**：
- 一个用户可能通过多个渠道触达，如何归因？
- 建议采用「最后点击归因」，简单且实用
- 高级场景可用「多触点归因」

代码逻辑解析：
```python
# 简单法
cac = total_cost / total_new_users

# 精确法（按渠道）
for channel in channels:
    cac_channel = channel_cost / channel_new_users
```

### 3.3 同期群分析

**按注册月份分组**：
- 将用户按注册月份分成同期群
- 每个同期群的用户数为该月新注册用户数
- 追踪每个同期群在后续月份的留存和收入

**留存率矩阵的计算逻辑**：
- 行：同期群（注册月份）
- 列：月份偏移（0, 1, 2, ...）
- 值：该同期群在该月份的留存率

**收入增长曲线的绘制方法**：
- 对每个同期群，计算累计收入
- 绘制收入随时间的变化曲线
- 对比不同同期群的收入增长

代码逻辑解析：
```python
# 同期群留存矩阵
for cohort in cohorts:
    for month_offset in range(max_months):
        retention = active_users / cohort_size
# 同期群收入曲线
for cohort in cohorts:
    cumulative_revenue = cumsum(monthly_revenue)
```

### 3.4 回报周期

**逐月累计收入 vs CAC**：
- 每个月计算累计收入
- 当累计收入 >= CAC 时，该月即为回报周期

**找到交叉点的逻辑**：
- 线性插值法：在两个月份之间找到精确的交叉点
- 回报周期 = CAC / 月ARPU（简化公式）

代码逻辑解析：
```python
# 逐月累计收入
cumulative = np.cumsum(monthly_revenue)
# 找到交叉点
payback_month = cac / arpu  # 简化公式
```

## 四、图表深度剖析（图1~图5）

### 图1: LTV/CAC 比值仪表盘

![LTV/CAC比值仪表盘](01_ltv_cac_ratio.png)

**是什么**：展示 LTV/CAC 综合比值的仪表盘，通常以仪表盘或大数字卡片形式呈现。

**为什么选**：这是整个分析的核心指标，需要一眼看到商业模式健康度。

**怎么写**：
```python
# 仪表盘风格展示
fig, ax = plt.subplots()
ax.text(0.5, 0.5, f'{ltv_cac_ratio:.1f}', fontsize=48, ha='center')
```

**长什么样**：大号数字居中展示，辅以颜色编码（绿色=健康，红色=不健康）。

**怎么读**：比值 >3 为健康，>5 为优秀，<3 需优化。

**结论怎么来**：本项目 LTV/CAC = 22.3，远超健康线，商业模式非常健康。

### 图2: LTV vs CAC 散点图

![LTV vs CAC散点图](02_ltv_cac_scatter.png)

**是什么**：以 CAC 为横轴、LTV 为纵轴的散点图，每个点代表一个渠道。

**为什么选**：直观展示各渠道的 LTV/CAC 关系，识别高效渠道。

**怎么写**：
```python
plt.scatter(cac_values, ltv_values)
for i, channel in enumerate(channels):
    plt.annotate(channel, (cac_values[i], ltv_values[i]))
```

**长什么样**：散点分布在坐标平面上，45度线以上为健康区域。

**怎么读**：越靠近左上角的渠道 LTV/CAC 最优。

**结论怎么来**：自然搜索渠道位于左上角，LTV/CAC 最优。
