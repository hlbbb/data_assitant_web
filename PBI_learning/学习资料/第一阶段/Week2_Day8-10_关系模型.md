## 一、为什么需要关系模型?

### 问题场景

假设你想看:
- 各地区的销售额
- 各产品的销售额
- 各客户的订单数量

但是:
- 销售表里只有"地区ID"(R001),没有地区名称
- 销售表里只有"产品ID"(P001),没有产品名称
- 销售表里只有"客户ID"(C001),没有客户姓名

**怎么办?**

你需要把销售表和其他表"连接"起来,这就叫**建立关系**。

---

## 二、关系模型的基本概念

### 1. 事实表(Fact Table)

**事实表**: 存储业务数据的表。

**特点**:
- 数据量大(比如销售表有 50 条订单)
- 包含数值字段(金额、数量等)
- 包含维度表的ID(外键)

**我们的例子**:
- 销售事实表 = 事实表

---

### 2. 维度表(Dimension Table)

**维度表**: 存储描述信息的表。

**特点**:
- 数据量小(比如产品表只有 6 个产品)
- 包含描述字段(名称、类别等)
- 包含唯一ID(主键)

**我们的例子**:
- 产品维度表 = 维度表
- 客户维度表 = 维度表
- 员工维度表 = 维度表
- 地区维度表 = 维度表
- 日期维度表 = 维度表

---

### 3. 星型模型(Star Schema)

**星型模型**: 事实表在中心,维度表围绕在周围。

**形状**:
```
        产品维度表
             ↓
客户维度表 → 销售事实表 ← 员工维度表
             ↓
        日期维度表
             ↓
        地区维度表
```

就像星星一样,中心是事实表,周围是维度表。

---

### 4. 一对多关系

**一对多关系**: 一个维度记录对应多个事实记录。

**举例**:

产品维度表:
```
P001 - iPhone 15 Pro (一条记录)
```

销售事实表:
```
ORD001 - P001 - iPhone订单 (第一条)
ORD004 - P001 - iPhone订单 (第二条)
ORD009 - P001 - iPhone订单 (第三条)
...
```

**关系**:
- 一个产品(P001)对应多个订单
- 这就是"一对多关系"

**表达方式**:
```
产品维度表 (1) → 销售事实表 (多)
```

## 三、Power BI 如何建立关系

### 方法 1: 自动建立

Power BI 会自动识别相同字段名:

比如:
- 销售事实表有"产品ID"
- 产品维度表也有"产品ID"

Power BI 会自动建立关系。

---

### 方法 2: 手动建立

如果字段名不同,或自动关系有问题,需要手动建立。

---

### 方法 3: 使用"管理关系"窗口

这是最推荐的方法,可以查看和修改所有关系。

---

## 四、建立关系的实际操作

### 步骤 1: 打开"管理关系"

位置: 开始 → 管理关系

你会看到一个关系图界面:
```
┌─────────────────────────────────┐
│                                 │
│   [销售事实表]                  │
│                                 │
│   [产品维度表] [客户维度表]     │
│                                 │
│   其他表...                     │
│                                 │
└─────────────────────────────────┘
```

---

### 步骤 2: 查看现有关系

如果 Power BI 已经自动建立了关系,你会看到连线:
- 线连接两个表
- 线上有"1"和"*"标记(表示一对多)

**检查是否正确**:
| 关系 | 从表 | 到表 | 字段 |
|------|------|------|------|
| 1 | 产品维度表(1) | 销售事实表(*) | 产品ID |
| 2 | 客户维度表(1) | 销售事实表(*) | 客户ID |
| 3 | 员工维度表(1) | 销售事实表(*) | 员工ID |
| 4 | 地区维度表(1) | 销售事实表(*) | 地区ID |
| 5 | 日期维度表(1) | 销售事实表(*) | 日期 |

---

### 步骤 3: 建立缺失的关系

如果某些关系没有建立,点击"新建":

**例子**: 建立销售表和产品表的关系

1. 点击"新建"
2. 选择表:
   - 表1: 产品维度表
   - 表2: 销售事实表
3. 选择字段:
   - 字段1: 产品ID
   - 字段2: 产品ID
4. 关系方向: 产品维度表(1) → 销售事实表(*)
5. 点击确定

---

### 步骤 4: 建立员工表和地区表的关系

**特殊情况**: 员工表也需要关联地区表

1. 点击"新建"
2. 选择表:
   - 表1: 地区维度表
   - 表2: 员工维度表
3. 选择字段:
   - 字段1: 地区ID
   - 字段2: 地区ID
4. 关系方向: 地区维度表(1) → 员工维度表(*)
5. 点击确定

---

## 五、关系属性设置

每个关系有一些属性可以设置:

### 1. 交叉筛选方向

**默认**: 单向筛选

```
产品表(1) → 销售表(*)
```

意思是:
- 选择某个产品 → 筛选销售表的数据
- 但不能反向筛选(选择某个订单 → 筛选产品表)

**双向筛选**:

```
产品表(1) ↔ 销售表(*)
```

意思是:
- 可以双向筛选

**什么时候用双向?**

大多数情况用单向就够了。
特殊场景才用双向(比如高级筛选)。

---

### 2. 激活/非激活关系

**激活关系**: 默认生效的关系

**非激活关系**: 临时不生效,需要时才用

**场景**: 比如员工表有两个地区字段(工作地区、居住地区),需要建立两个关系,但只能激活一个。

---

## 六、验证关系是否正确

### 方法 1: 看图表

回到你的销售仪表板:

**检查各地区销售额柱状图**:
- 如果看到"华北区"、"华东区"、"华南区" → 关系正确 ✓
- 如果看到"R001"、"R002"、"R003" → 关系错误 ✗

**原因**: 关系没建立,Power BI 直接用了地区ID。

---

### 方法 2: 看管理关系图

打开"管理关系":
- 应该看到 6 条连线(6 个关系)
- 每条线上有"1"和"*"标记

---

### 方法 3: 测试筛选

在图表上:
1. 点击"华北区"
2. 其他图表应该只显示华北区的数据
3. 如果所有图表都正确筛选 → 关系正确 ✓

---

## 七、完整关系模型

### 我们的数据模型关系

```
产品维度表
    ↓ (产品ID)
    ↓
销售事实表 ← (客户ID) ← 客户维度表
    ↓ (日期)
    ↓
日期维度表

销售事实表 ← (员工ID) ← 员工维度表 ← (地区ID) ← 地区维度表
```

**6 条关系**:
1. 产品维度表 → 销售事实表 (产品ID)
2. 客户维度表 → 销售事实表 (客户ID)
3. 员工维度表 → 销售事实表 (员工ID)
4. 地区维度表 → 销售事实表 (地区ID)
5. 日期维度表 → 销售事实表 (日期)
6. 地区维度表 → 员工维度表 (地区ID)

## 八、常见问题

### Q1: 关系方向搞反了?

**症状**: 图表筛选不工作

**解决**:
- 确保维度表(1) → 事实表(*)
- 不要搞成事实表(1) → 维度表(*)

---

### Q2: 多对多关系?

**症状**: 两个表都有重复值

**举例**:
- 表A的ID有重复
- 表B的ID也有重复
- 无法建立一对多关系

**解决**:
- 检查维度表的ID是否唯一
- 如果维度表有重复,说明数据有问题

---

### Q3: 关系建立后图表还是显示ID?

**原因**:
- 关系没建立
- 或者字段选错了

**解决**:
1. 重新打开"管理关系"
2. 检查关系是否存在
3. 删除重建关系

---

## 九、关系模型最佳实践

### 1. 星型模型

**推荐**: 使用星型模型

```
事实表在中心,维度表围绕
```

**好处**:
- 性能最好
- 易于理解
- 易于维护

---

### 2. 维度表要小

**原则**: 维度表数据量应该小

**例子**:
- 产品表: 6 条(很小) ✓
- 客户表: 7 条(很小) ✓
- 销售表: 50 条(相对大) ✓

---

### 3. 字段命名一致

**原则**: 关联字段应该名称一致

**例子**:
- 销售表的"产品ID"
- 产品表的"产品ID"
- 名称相同,Power BI 自动识别 ✓
