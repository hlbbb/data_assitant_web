## 一、高级数据建模

### 多事实表模型

**场景**: 一个企业有多个业务线,每个业务线一个事实表

**例子**:
- 销售事实表: 订单数据
- 库存事实表: 库存数据
- 财务事实表: 财务数据

---

### 共享维度表

多个事实表可以共享维度表:

```
        产品维度表
        ↓      ↓
销售事实表    库存事实表
        ↓      ↓
        日期维度表
```

**好处**:
- 减少数据冗余
- 统一维度定义
- 便于跨业务分析

---

### 实际操作: 添加库存事实表

**步骤 1**: 创建库存事实表

假设我们添加库存数据:
```
产品ID, 日期, 库存数量, 库存金额
P001, 2024-01-01, 100, 450000
P002, 2024-01-01, 50, 150000
...
```

**步骤 2**: 导入 Power BI

**步骤 3**: 建立关系:
- 产品维度表 → 库存事实表(产品ID)
- 日期维度表 → 库存事实表(日期)

**步骤 4**: 创建库存分析:
```dax
总库存数量 = SUM('库存事实表'[库存数量])
总库存金额 = SUM('库存事实表'[库存金额])
```

## 二、多对多关系

### 什么是多对多关系?

**场景**: 一个客户可以属于多个销售团队,一个团队可以有多个客户

```
客户表 ←→ 团队表
```

两边都有重复值,无法直接建立一对多关系。

---

### 解决方案: 桥接表

创建一个桥接表:
```
客户团队桥接表
客户ID, 团队ID
C001, T001
C001, T002
C002, T001
```

**关系**:
```
客户表(1) → 桥接表(*) ←(1) 团队表
```

---

### 多对多关系的度量值

```dax
团队客户数 =
CALCULATE(
    DISTINCTCOUNT('客户表'[客户ID]),
    '团队表'
)
```

## 三、角色扮演维度

### 什么是角色扮演维度?

**场景**: 一个维度表在事实表中有多个外键

**例子**: 销售表有"订单日期"和"发货日期",都关联日期维度表

```
日期维度表
    ↓ (订单日期)
销售事实表
    ↓ (发货日期)
日期维度表(另一个副本)
```

---

### 解决方案 1: 创建日期表副本

**步骤 1**: 复制日期维度表,命名为"发货日期维度表"

**步骤 2**: 建立关系:
- 日期维度表 → 销售事实表(订单日期)
- 发货日期维度表 → 销售事实表(发货日期)

---

### 解决方案 2: 使用非激活关系

**步骤 1**: 建立两个关系,其中一个设为非激活

**步骤 2**: 使用时激活:
```dax
发货日期销售额 =
CALCULATE(
    SUM('销售事实表'[金额]),
    USERELATIONSHIP('销售事实表'[发货日期], '日期维度表'[日期])
)
```

## 四、性能优化

### 1. 数据模型优化

**原则**:
- 使用星型模型
- 减少关系数量
- 避免双向筛选
- 维度表要小

---

### 2. DAX 优化

#### 使用变量

**优化前**:
```dax
销售额占比 =
DIVIDE(
    SUM('销售事实表'[金额]),
    CALCULATE(SUM('销售事实表'[金额]), ALL('产品维度表'))
)
```

**优化后**:
```dax
销售额占比 =
VAR 当前销售额 = SUM('销售事实表'[金额])
VAR 总销售额 = CALCULATE(SUM('销售事实表'[金额]), ALL('产品维度表'))
RETURN
    DIVIDE(当前销售额, 总销售额)
```

**好处**: 总销售额只计算一次,提高性能。

---

#### 避免复杂迭代

**优化前**:
```dax
利润 = SUMX('销售事实表', [金额] - RELATED('产品维度表'[成本价]) * [数量])
```

**优化后**: 在 Power Query 中预先计算利润列

## 五、增量刷新

### 什么是增量刷新?

**增量刷新** = 只刷新新增的数据,不刷新全部数据

**好处**:
- 刷新速度快
- 减少资源消耗
- 支持大数据量

---

### 配置增量刷新

**步骤 1**: 右键表 → 增量刷新

**步骤 2**: 设置参数:
- 存档起始日期: 5年前
- 刷新开始日期: 1年前
- 仅刷新最近: 10天

**步骤 3**: 应用

**效果**:
- 历史数据(5年前-1年前): 不刷新
- 最近数据(最近10天): 每次刷新
- 中间数据(1年前-10天前): 按需刷新

---

### 增量刷新的要求

- 数据源必须有日期列
- 日期列必须是日期类型
- 需要配置数据网关

## 六、复合模型

### 什么是复合模型?

**复合模型** = 混合使用导入模式和 DirectQuery 模式

**场景**:
- 历史数据量大,使用 DirectQuery
- 最近数据量小,使用导入模式

---

### 配置复合模型

**步骤 1**: 导入部分表(导入模式)

**步骤 2**: 连接其他表(DirectQuery 模式)

**步骤 3**: 建立关系

---

### 优缺点

**优点**:
- 历史数据不占用内存
- 最近数据查询快

**缺点**:
- 配置复杂
- DirectQuery 查询慢

---

## 七、聚合表

### 什么是聚合表?

**聚合表** = 预先聚合的数据表

**场景**: 销售表有 1 亿行,按天聚合后只有 365 行

---

### 创建聚合表

**步骤 1**: 在 Power Query 中创建聚合表:
- 按日期分组
- 汇总销售额

**步骤 2**: 设置聚合映射:
- 右键聚合表 → 管理聚合
- 设置映射关系

**效果**: 查询时自动使用聚合表,提高性能。

## 九、常见问题

### Q1: 多对多关系导致数据重复?

**原因**: 没有使用桥接表

**解决**: 创建桥接表,建立正确的关系

---

### Q2: 性能很慢?

**原因**: 数据模型或 DAX 不优化

**解决**:
- 使用星型模型
- 使用变量
- 减少迭代函数
- 使用聚合表

---

### Q3: 增量刷新配置失败?

**原因**: 数据类型错误或网关问题

**解决**:
- 确保日期列是日期类型
- 配置数据网关
- 检查 Power Query 步骤
